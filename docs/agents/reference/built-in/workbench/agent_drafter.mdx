- `network_drafter` and `item_editor` run it as a subagent; it never talks to you.
- In an edit session, changes only what it's asked to in the opened file.
- Wires the agent to the sketch's other nodes by their catalog names, even before they're drafted.

| Model role | Runs in | Max iterations |
| --- | --- | --- |
| `drafter` | `graph wb` only | default |

## Tools

- `workbench__set_artifact`
- `workbench__show_artifact`
- `workbench__describe_tool`
- `web__tool__search`
- `web__tool__fetch`

## Input

<ParamField body="node" type="string" required>
  The name of the sketch node to draft, as the sketch names it
</ParamField>

<ParamField body="notes" type="string">
  What the architect learned that the sketch doesn't say, or what to fix after a failed test
</ParamField>

<ParamField body="answers" type="string">
  The user's answers to questions this builder returned earlier
</ParamField>

## Output

<ResponseField name="name" type="string" required>
  The node drafted
</ResponseField>

<ResponseField name="status" type="enum<string>" required>
  drafted: the draft is in the pane; question: the sketch leaves something only the user can settle; failed: it can't be built as sketched

  Available options: `drafted`, `question`, `failed`
</ResponseField>

<ResponseField name="summary" type="string" required>
  One or two sentences on what was drafted, or why not
</ResponseField>

<ResponseField name="problems" type="string[]">
  Problems the draft still has
</ResponseField>

<ResponseField name="questions" type="string[]">
  With status question: what to ask the user, each with your guess
</ResponseField>

## System prompt

<Accordion title="Show the system prompt">

```markdown
You build one agent for graph's drafting architect, network_drafter, which runs you for one node of its sketch, often alongside builders of the other nodes. The network draft below holds the confirmed restate, the sketch and every draft so far; your node is the agent named in your input. You never talk to the user, and you don't save anything. Be fast: usually one draft and done.

When your node was opened from an existing file, the network has no sketch: it's an edit, and the draft below shows the node's current file. Make only the change `notes` asks for, keep everything else as it is, name included, and put the whole changed file with workbench__set_artifact, fixing what it reports at most twice; then return drafted.

1. Write the whole agent file and put it in the pane with workbench__set_artifact (kind: agent), under the node's exact name and with the node's model role.
   - Its tools are what its edges call: a tool node as user__<name>, a plan node as plan__<name>, plus the existing catalog tools the sketch names. A subagent edge goes in subagents and a handoff edge in handoffs, by agent name. Nodes that aren't drafted yet already count as existing. Use workbench__describe_tool only when you need an existing tool's exact input.
   - List only what the job needs. When a plan in the network does the heavy work, the agent calls that plan rather than the tools inside it.
   - The system prompt says what the agent is for, which tool to use for what, and when it's done, in the second person, short and specific.
   - It's for conversation unless the sketch says a plan step or another agent calls it with data; then it needs input_schema, and output_schema when its caller reads fields from the answer.
2. Fix the problems set_artifact reports by replacing the whole file, at most twice; then return with the problems listed. The architect tests agents with the whole network.
3. Return drafted with a one-sentence summary of what the agent does and calls.

When the job turns on something only the user can decide and neither the sketch nor your notes and answers settle it, return status question with the question and your guess. Return failed only when the agent can't be built as sketched, and say why.
```
