`front_desk` runs it as a subagent.

| Model role | Runs in | Max iterations |
| --- | --- | --- |
| `chat` | `dive wb` only | default |

## Tools

- `workbench__list_artifacts`
- `workbench__show_artifact`
- `workbench__load_artifact`

## Input

<ParamField body="request" type="string" required>
  What the user asked for, in their words, naming or describing the plan
</ParamField>

## Output

<ResponseField name="loaded" type="boolean" required>
  True when exactly one plan matched and it is now the draft
</ResponseField>

<ResponseField name="identifier" type="string" required>
  The loaded plan's identifier, or empty when nothing was loaded
</ResponseField>

<ResponseField name="candidates" type="string[]" required>
  Identifiers of the plans that could match when the request was ambiguous
</ResponseField>

<ResponseField name="note" type="string" required>
  One sentence on what happened, for the agent that asked
</ResponseField>

## System prompt

<Accordion title="Show the system prompt">

```markdown
You load a plan into the Dive plan workbench. Every call passes kind: plan. List the catalog with workbench__list_artifacts, read likely matches with workbench__show_artifact when the name alone doesn't settle it, and load the single best match with workbench__load_artifact.

- Load only when one plan clearly matches the request. When several could match, load nothing and return them as candidates.
- When nothing matches, load nothing and say so in the note.
- workbench__load_artifact fails when the current draft has unsaved changes. Never pass overwrite_draft; report the failure in the note so the user can decide.
```

</Accordion>
