Dive ships as a single binary and a container image — grab whichever fits. Current release: {{release_version}}.

## Release binaries

Tagged releases publish binaries for macOS (arm64) and Linux (x86_64) with SHA-256 checksums.

<BinaryDownloads />

Or from the command line:

<Tabs>
  <Tab title="macOS (arm64)">
    ```bash
    curl -fsSLO "https://github.com/loon-rocks/dive/releases/download/{{release_version}}/dive-{{release_version}}-macos-arm64.tar.gz"
    tar xzf dive-*.tar.gz && install -m 0755 dive ~/.local/bin/
    dive --help
    ```
  </Tab>
  <Tab title="Linux (x86_64)">
    ```bash
    curl -fsSLO "https://github.com/loon-rocks/dive/releases/download/{{release_version}}/dive-{{release_version}}-linux-x86_64.tar.gz"
    tar xzf dive-*.tar.gz && install -m 0755 dive ~/.local/bin/
    dive --help
    ```
  </Tab>
</Tabs>

<Info>
  On macOS, the first run of a freshly downloaded binary pauses ~1s while Gatekeeper scans it. Every run after that is instant.
</Info>

## Container image

Each release also publishes [ghcr.io/loon-rocks/dive](https://github.com/loon-rocks/dive/pkgs/container/dive) with git, gh, jq and curl installed, ready to use in CI:

```bash
docker run --rm \
           -e ANTHROPIC_API_KEY \
           -e DIVE_STORAGE=memory \
           -v "$PWD:/work" \
           -w /work \
           ghcr.io/loon-rocks/dive:{{release_version}} plan list
```

## Requirements

| Requirement | Notes |
| --- | --- |
| macOS (arm64) or Linux (x86_64) | the platforms release binaries are published for |
| An LLM provider key | e.g. `ANTHROPIC_API_KEY` — see [Quickstart](/quickstart) |

## First-run notes

- Dive creates its [data directory](/reference/data-directory) at `~/.local/share/dive/` on first use (configurable via `[settings] data_dir`).
- State is plain files under the data directory, safe under concurrent runs. Use `DIVE_STORAGE=memory` for ephemeral runs that should leave nothing behind.

## Upgrading from graph

Dive was called graph until v0.17.0. Dive still reads graph's files and settings, so an existing setup keeps working:

| graph | Dive | Read when |
| --- | --- | --- |
| `./.graph/` | `./.dive/` | the project has no `./.dive/` |
| `~/.config/graph/` | `~/.config/dive/` | there is no `~/.config/dive/` |
| `~/.local/share/graph/` | `~/.local/share/dive/` | there is no `~/.local/share/dive/` |
| `GRAPH_*` variables | `DIVE_*` variables | the `DIVE_` name is unset |
| credential store service `graph` | service `dive` | a name has no value under `dive` |
| `requires.graph` in `pack.toml` | `requires.dive` | the manifest is version 1 |

Each run that falls back to an old name prints a warning on stderr saying what to rename. Dive never moves, rewrites or deletes the old files. Rename the directories yourself, set the `DIVE_` variables, and store secrets again with `dive secret set` to clear the warnings. `dive secret rm` removes a name under both services. Exec tools in packs get both `DIVE_PACK_DIR` and `GRAPH_PACK_DIR`.

Support for the graph names ends at v1.0.
