The workbench is a full-screen terminal UI where you build agents, plans and tools by talking to graph's built-in agents, then run and debug them in the same window.

## Open it

```bash
graph workbench
```

It opens at the front desk, which asks what you want to build. To go straight to a mode, name it, and optionally the file to open:

```bash
graph workbench plan unreleased_changes
graph workbench agent release_notes
graph workbench tool merged_prs
```

`graph wb` is short for `graph workbench`. The workbench needs an interactive terminal. In scripts and CI, use [`graph plan run`](/plans/guides/run-a-plan).

- **Chat**, on the left: you talk to the workbench's agents. The pane title names the agent you're talking to.
- **Workspace**, on the right, with three tabs:
  - <kbd>1</kbd> the network you're drafting, or the plan you're editing, with the selected row's detail below it.
  - <kbd>2</kbd> the tool catalog the agents draft from.
  - <kbd>3</kbd> the latest run.

## Who you're talking to

Whatever you build, a single tool, a plan, an agent or several working together, the front desk hands you to the drafting architect, `network_drafter`. It interviews you one question at a time until the problem is clear, confirms what it'll build, and sketches the network in the workspace: each tool, plan and agent, the model role it runs on, and how they connect. It designs for small models, composed plans and map/reduce before a large model with many tools, and says so when you ask for something more expensive than the job needs.

When you say to build it, the architect has the tool, plan and agent drafters write each piece, tests the whole network, and saves it when you're ready. To open an existing plan, the front desk loads it and hands you to the plan editor; when a plan needs a new tool, the plan editor hands you to the architect and gets you back once it's saved.

To switch by hand, type `/agent <name>` in the chat. See [Built-in agents](/agents/reference/built-in-agents) for what each one does.

## Saving

<kbd>Ctrl</kbd>+<kbd>S</kbd> saves what's in the workspace: a drafted network all at once, tools to `./.graph/tools/`, plans to `./.graph/plans/` and agents to `./.graph/agents/`, or the plan you're editing. A file you opened is saved in place.

## Keys

<kbd>Tab</kbd> moves focus between chat and the workspace. Most keys act on the workspace, so press <kbd>Tab</kbd> first when you're typing in chat.

| Key | Does |
| --- | --- |
| <kbd>Enter</kbd> | Chat: send. <kbd>Alt</kbd>+<kbd>Enter</kbd> adds a new line |
| <kbd>1</kbd> <kbd>2</kbd> <kbd>3</kbd> | Switch workspace tab. <kbd>Alt</kbd>+<kbd>1</kbd> works from chat |
| <kbd>j</kbd> <kbd>k</kbd> | Select a step or tool |
| <kbd>e</kbd> | Edit the selected step in a form |
| <kbd>a</kbd> / <kbd>A</kbd> | Add a step after / before the selected one |
| <kbd>PgUp</kbd> <kbd>PgDn</kbd> | Scroll the focused pane |
| <kbd>v</kbd> | Validate the plan |
| <kbd>r</kbd> | Run the plan |
| <kbd>g</kbd> | Debug run: pause at each breakpoint, or before every call when there are none |
| <kbd>b</kbd> | Toggle a breakpoint on the selected step |
| <kbd>u</kbd> | Undo the last time an agent replaced the draft. Press again to redo |
| <kbd>x</kbd> <kbd>x</kbd> | Discard the drafted network |
| <kbd>Ctrl</kbd>+<kbd>S</kbd> | Save |
| <kbd>?</kbd> | Show the keys |
| <kbd>q</kbd> | Quit |

While a debug run is paused:

| Key | Does |
| --- | --- |
| <kbd>n</kbd> | Run this call and pause at the next one |
| <kbd>c</kbd> | Continue to the next breakpoint or error |
| <kbd>s</kbd> | Skip this call and give it a result, or replace a failed call's result |
| <kbd>a</kbd> | Abort the run |

## Mouse

| Action | Does |
| --- | --- |
| Click a pane | Focus it |
| Click a tab | Switch to it |
| Click a row | Select it |
| Double-click a row | Edit it |
| Scroll | Scroll the pane under the pointer |

## Logs

The workbench writes its log to `workbench.log` in the [data directory](/reference/data-directory), not to the terminal. Set `GRAPH_WORKBENCH_LOG` or `[workbench] log_path` to change the path, and `GRAPH_LOG` to change what it records.
