`release_summary` finds the latest release, calls `changes_since` for the commits since it, and summarizes them.

<RequestExample>

```yaml .graph/plans/release_summary.yaml
version: 2
identifier: release_summary
name: Release summary
description: Summarizes the commits merged since the latest GitHub release.
steps:
- id: release
  tool_name: github__tool__gh_release
  input: {}
- id: changes
  tool_name: plan__changes_since
  input:
    base: '{{release.tag}}'
finish:
  solver:
    query_to_answer: Summarize the {{changes.count}} commits since {{release.tag}} in three one-line bullet points.
    data:
      commits: '{{changes.commits}}'
```

```yaml .graph/plans/changes_since.yaml
version: 2
identifier: changes_since
name: Changes since
description: The commits merged since a git ref.
input_schema:
  type: object
  required:
  - base
  properties:
    base:
      type: string
      description: The ref to start after, such as a release tag
steps:
- id: commits
  tool_name: github__tool__git_log
  input:
    base: '{{input.base}}'
    head: HEAD
finish:
  output:
    count: '{{commits.count}}'
    commits: '{{commits.commits}}'
```

</RequestExample>

## Call the plan from a step

The `changes` step calls `changes_since` as `plan__changes_since`. Its `input` matches `changes_since`'s `input_schema`, and later steps read the result through `changes`, the same keys as `changes_since`'s `finish.output`: `{{changes.count}}` and `{{changes.commits}}`.

## Validate it

```bash
graph plan validate release_summary
```

```text
ok: 'release_summary' — 2 steps
```

## Run it

```bash
graph plan run release_summary
```
