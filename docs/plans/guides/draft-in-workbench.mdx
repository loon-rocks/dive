## Draft the plan

<Steps>
  <Step title="Open the workbench in plan mode">
    ```bash
    graph workbench plan
    ```
  </Step>
  <Step title="Describe the goal">
    Say what the plan should produce and from what:

    ```text
    a plan that writes a one-line release
    note for each commit since the latest
    GitHub release, from its subject and
    the files it changed
    ```

    The plan drafter finds the tools for each part of the goal, writes the plan, checks it, and puts it in the pane:

    <Frame caption="The drafted plan in the pane: the release, the commits since it, each commit's changed files, and one infer step that writes the notes.">
      <img src="/images/workbench/plan-drafted.svg" alt="The workbench after drafting: the goal and the plan drafter's summary on the left, and the release_notes_since_latest_release plan on the right with steps release, commits, a file_changes map over changed and row, notes, and the output, marked valid." />
    </Frame>
  </Step>
  <Step title="Answer its questions">
    The drafter may ask for clarification on statuses or labels that it needs to draft the plan. Answer the questions in the form to continue.

    <Frame caption="The drafter's questions, each filled in with its guess.">
      <img src="/images/workbench/plan-drafting-questions.svg" alt="The workbench's answer form over the chat, asking whether merge commits should get a release note (no) and whether to leave out commits that only change .github/, with a field for anything else the planner should know." />
    </Frame>
  </Step>
  <Step title="Rename it">
    The plan editor takes over once the draft is in the pane. Ask it for the identifier you want:

    ```text
    rename it unreleased_changes
    ```
  </Step>
  <Step title="Save">
    Press <kbd>Ctrl</kbd>+<kbd>S</kbd>. graph writes the plan to `./.graph/plans/unreleased_changes.yaml`.
  </Step>
</Steps>

## Run the plan

```bash
graph plan run unreleased_changes
```
