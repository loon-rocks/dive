## Behavior

- Posts one comment per entry that has a line anchor.
- Entries without an anchor, or with one GitHub rejects, come back unposted.
- Deletes earlier comments with the same marker first, so reruns replace them.
- Has side effects.

| Pack | Kind | Effect |
| --- | --- | --- |
| [`github`](/tools/reference/packs/github): add `"github"` to `[tools].packs` | `exec` | Has side effects |

## Input

<ParamField body="pr" type="integer" required>
  Pull request number
</ParamField>

<ParamField body="head_sha" type="string" required>
  Commit the comments anchor to — the PR head sha
</ParamField>

<ParamField body="marker" type="string" required>
  Stable identifier embedded in every comment as a hidden tag; the next run with the same marker deletes those comments before posting. Use one marker per plan, e.g. "graph:pr_review".
</ParamField>

<ParamField body="comments" type="object[]" required>
  Comment entries. Keys beyond path/line/side/body are ignored for posting but preserved in the output.
</ParamField>

<ParamField body="comments.[].path" type="string" required>
  File path within the diff
</ParamField>

<ParamField body="comments.[].line" type="integer">
  Line in the new file; must be part of the diff. Omit when unknown — the entry passes through unposted.
</ParamField>

<ParamField body="comments.[].side" type="enum<string>">
  Diff side; defaults to RIGHT

  Available options: `LEFT`, `RIGHT`
</ParamField>

<ParamField body="comments.[].body" type="string" required>
  Markdown comment body
</ParamField>

## Output

<ResponseField name="comments" type="any[]">
  The input entries in order, each with url added when its comment posted; entries without a line, or rejected by the API, come back without one.
</ResponseField>
