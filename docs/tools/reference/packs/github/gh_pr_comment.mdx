## Behavior

- With `marker`, edits the comment carrying that marker, so each plan keeps its own comment.
- Without one, updates your most recent comment on the pull request.
- Has side effects.

| Pack | Kind | Effect |
| --- | --- | --- |
| [`github`](/tools/reference/packs/github): add `"github"` to `[tools].packs` | `exec` | Has side effects |

## Input

<ParamField body="pr" type="integer" required>
  Pull request number
</ParamField>

<ParamField body="body" type="string" required>
  Markdown comment body
</ParamField>

<ParamField body="marker" type="string" default="">
  Stable identifier embedded in the body as a hidden tag; the next run with the same marker edits that comment. Use one marker per plan (e.g. "graph:pr_review:summary") when several plans comment on the same PR. Omit to edit the token identity's most recent comment instead.
</ParamField>
