## Behavior

- Returns the message's `ts`. Pass it as `thread_ts` in a later call to reply in that thread.
- A post Slack refuses, such as an unknown channel or a missing scope, fails the step.
- `text` uses Slack mrkdwn, not GitHub markdown.
- Has side effects.

| Pack | Kind | Effect |
| --- | --- | --- |
| [`slack`](/tools/reference/packs/slack): add `"slack"` to `[tools].packs` | `exec` | Has side effects |

## Input

<ParamField body="channel" type="string" required>
  Target channel: a channel ID (C…/G…/D…, from the channel's "Copy link"), or "#channel-name" for a public channel the bot has joined. IDs are the reliable form; names depend on lookup.
</ParamField>

<ParamField body="text" type="string" required>
  Message body in Slack mrkdwn — *bold*, _italic_, `code`, `<https://url|label>` — not GitHub markdown. Also the notification text every channel member sees.
</ParamField>

<ParamField body="thread_ts" type="string" default="">
  Reply in an existing thread: the parent message's ts (the ts an earlier slack_post_message returned). Omit to post a new top-level message.
</ParamField>

## Output

<ResponseField name="channel" type="string">
  Resolved channel ID — pass it back when replying in-thread
</ResponseField>

<ResponseField name="ts" type="string">
  Message timestamp; the thread_ts for replies to this message
</ResponseField>

<ResponseField name="permalink" type="string | null">
  Link to the message; null when the permalink lookup did not answer
</ResponseField>
