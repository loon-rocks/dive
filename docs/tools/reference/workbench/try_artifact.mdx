## Behavior

- A tool runs once on a sample input, after you approve it. Name it when several tool drafts are open.
- A tool whose `env` needs a secret that isn't set doesn't run: the result is `status: missing_secrets`, as with `workbench__test_network`.
- A plan runs with its steps streaming to the pane. `gated` or `breakpoints` make it a debug run that pauses for you.
- Agents and network plans are tried with `workbench__test_network`.

| Available to | Effect |
| --- | --- |
| Workbench agents only | Has side effects |

## Input

<ParamField body="breakpoints" type="string[]">
  Plans only: top-level step ids to pause at. Implies gated; the run proceeds until a breakpoint (or a failing call) and pauses for the USER.
</ParamField>

<ParamField body="gated" type="boolean">
  Plans only: debug run, pausing for the user's decisions and breaking on errors. Default false.
</ParamField>

<ParamField body="input" type="object">
  A tool's sample input matching its input_schema, or a plan's input validated against its input_schema
</ParamField>

<ParamField body="kind" type="enum<string>" required>
  What the draft is

  Available options: `plan`, `agent`, `tool`
</ParamField>

<ParamField body="name" type="string">
  Tools: which tool draft, when there are several
</ParamField>

<ParamField body="purpose" type="string">
  Tools: one sentence the user reads before approving the run, saying what it checks, e.g. "Check it returns README.md's text and refuses a path outside the project."
</ParamField>
