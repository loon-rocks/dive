## Send traces to Langfuse

Point `endpoint` at your Langfuse region's OTLP URL and authenticate with your project's API keys in `headers`:

```toml
[telemetry]
endpoint = "https://cloud.langfuse.com/api/public/otel"

[telemetry.headers]
Authorization = "Basic ${LANGFUSE_AUTH}"
"x-langfuse-ingestion-version" = "4"
```

- `endpoint` is the base URL. Dive adds `/v1/traces` itself. For the US region, use `https://us.cloud.langfuse.com/api/public/otel`.
- Set `LANGFUSE_AUTH` in your environment to the base64 encoding of `<public key>:<secret key>`. Header values can reference environment variables, so the keys stay out of the file.
- `x-langfuse-ingestion-version = "4"` makes traces show up in Langfuse right away instead of after a delay.

Langfuse groups the traces of one thread, or one workbench session, into a session.

## What a trace contains

- One trace per run or turn; steps, tool calls and model calls as spans
- Model, token usage and cost on each model call
- `capture_content` includes each call's input and output: prompts, responses, tool arguments and results. It's off unless you turn it on. Content is exported whole; set [`trace.clip_bytes`](/reference/configuration#param-trace-clip-bytes) to clip it
- `logs` exports logs too

Dive also keeps every turn's trace with its thread, whether or not telemetry is on. See [Thread traces](/reference/data-directory#thread-traces).

## Check it worked

- Run `dive plan run` or `dive ask` and find the trace in the backend
