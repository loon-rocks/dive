Dive keeps its runtime state in one directory, `~/.local/share/dive` by default. Set [`settings.data_dir`](/reference/configuration#param-settings-data-dir) to move it. Dive creates the directory the first time it needs it.

## Layout

| Path | Contents |
| --- | --- |
| `FORMAT` | The directory's [file version](/reference/file-versions), as a single number. |
| `threads/<id>/meta.json` | A thread's title, timestamps, message count, the agent that owns it and the one that's active, the project it was started in, and its attachments. |
| `threads/<id>/entries.jsonl` | A thread's history, one entry per line: messages, handoffs between agents, and subagent runs. |
| `threads/<id>/spans.jsonl` | A thread's trace: every call each turn made, at any depth, one span per line. |
| `threads/<id>/.lock` | A lock file that keeps concurrent writers in order. |
| `files/<hash>.<ext>` | Files that tools return and that you attach, such as images, named by a SHA-256 hash of their contents. Only when [`[storage.files]`](/reference/configuration#param-storage-files) keeps files on disk, the default. |
| `cache/files/<hash>.<ext>` | Files downloaded from an S3 bucket, kept to 512 MB by dropping the least recently used. Safe to delete. |
| `shapes/<tool>.json` | The observed output of one tool: an inferred schema, an example, and how many times it was seen. |
| `workbench.log` | The workbench's log, appended across sessions. |

Every file is plain JSON or JSONL, so `cat` and `jq` can read it. Thread IDs are 12 hex characters. In a shape file name, any character other than a letter, digit, `_`, `.` or `-` is percent-encoded.

## Thread projects

`meta.json` records the project a thread was started in under `project`: the absolute path of the project's root folder, with symlinks resolved. A folder is a project when it has a `.dive` folder. A thread started anywhere else, or in `~/.config/dive`, is global and has no `project`, and so does every thread written before projects were recorded. `dive thread list` lists the current directory's threads; `--all` lists them all.

## Thread attachments

`meta.json` lists the things a thread works on under `attachments`, left out when there are none. Each attachment has a `kind`, plus fields of its own. A thread carries at most one attachment of each kind.

| Kind | Fields |
| --- | --- |
| `network` | The network draft of tools, plans and agents the drafting agents build in the thread, or the existing items an edit thread changes. `state` is `open`, `saved` or `discarded`, and `saved`, when present, says what was written where. `opened`, when present, lists the items the thread was opened on, each with its `kind` (`agent`, `plan` or `tool`) and `name`. The draft itself isn't stored: the opened items are read from their files and the edits are rebuilt from the thread's entries when the thread is opened again. |
| `evidence` | The call an edit thread is about, copied from the thread it came from so it outlives that thread: `thread`, the source thread's id; `call`, the call's id, when there is one; `item`, the agent, plan or tool it concerns, with its `kind` and `name`; `input`; `output` or `error`; `trace`, when the source thread recorded one: every plan, agent and tool call inside the call, and each model call an agent made, with its step path and the start of its output; `turn`, true when the edit is about a whole turn, whose `input` is the user's message and `output` the reply; and `focus`, when the user pointed at one step or model call inside it: its `span`, `name`, step path as `step`, `model` for a model call, the editable `item` it is when it is one, and its own `input` and `output` or `error`. A step's evidence is the call of the plan or agent that ran it, with the step as its focus. |

A thread gets an attachment only when something loads one: an agent calls `builtin__create_network` (a blank draft), `builtin__open_network` (an existing agent, plan or tool) or `builtin__attach_evidence` (a call from another thread), or you open an edit thread, which loads the items to edit and, when the edit started from a call, that call as evidence. Every agent active in the thread sees what's loaded.

## Thread entries

Each line of `entries.jsonl` is one entry. Every entry has these fields:

| Field | Contents |
| --- | --- |
| `seq` | The entry's position in the thread, counting from 0. |
| `at` | When the entry was written, in epoch milliseconds. Entries written together at the end of a turn share one value. |
| `author` | `user`, or the name of the agent that wrote the entry. |
| `kind` | `message`, `handoff` or `subagent_run`. The remaining fields depend on the kind. |

A user's `message` entry carries `images` when images were attached to it: their [file references](/integrating/mcp/guides/images-and-files), such as `blob:sha256-….png`. Dive loads those files and sends them to the model with the message on every turn.

A `message` entry written by an agent's turn can also carry:

| Field | Contents |
| --- | --- |
| `ms` | On a model reply, how long the model call took. On a tool result, how long the tool call took. In milliseconds. |
| `usage` | On a model reply only: `model`, the model that answered, plus `input_tokens`, `output_tokens`, `cache_creation_input_tokens` and `cache_read_input_tokens` for that call. |
| `span` | On a model reply, the span of the model call that wrote it. On a tool result, the span of the tool call. On a subagent run, the span of the call that ran the subagent. See [Thread traces](#thread-traces). |

These fields are left out when Dive has nothing to record: on user messages, handoffs, the messages of a turn that failed, and entries written before Dive recorded them. Entries written before spans existed may carry a `calls` field, which Dive no longer reads.

## Thread traces

Each line of `spans.jsonl` is one finished span, shaped like an [OpenTelemetry](https://opentelemetry.io/docs/concepts/signals/traces/) span. Each turn is one trace: its root span is the turn, and every model call, tool call, plan, plan step and subagent the turn ran is a span under it, at any depth. Spans are written when the turn ends, so a turn that fails or is cancelled leaves none.

| Field | Contents |
| --- | --- |
| `trace_id` | 32 hex characters, shared by every span of one turn. |
| `span_id` | 16 hex characters. Entries name their span by this id. |
| `parent_span_id` | The span this call was made from, left out on a turn's root. |
| `name` | The tool or agent name, `chat <model>` for a model call, or the active agent's name on the root. |
| `kind` | `turn`, `agent`, `plan`, `tool` or `model`. |
| `start_time_unix_nano`, `end_time_unix_nano` | When the call started and ended, in nanoseconds since the epoch. |
| `status` | `code`, `ok` or `error`, and on an error, its `message`. |
| `attributes` | Facts about the call, named after the OpenTelemetry [generative AI conventions](https://opentelemetry.io/docs/specs/semconv/gen-ai/) where one fits: `gen_ai.operation.name`, `gen_ai.tool.name`, `gen_ai.tool.call.id`, `gen_ai.agent.name`, `gen_ai.request.model`, `gen_ai.provider.name` and the `gen_ai.usage.*` token counts, plus `dive.role`, `dive.site`, `dive.cost_usd`, `dive.step.path` and `dive.plan.stack`. A call that fixes another call's structured output has `dive.role` `repair` and the validation error that started it in `dive.repair.reason`. |
| `input`, `output` | What the call was given and what it returned: a tool's arguments and result, a step's rendered input and result, a turn's message and reply. Model calls don't keep theirs. Kept only while [`trace.content`](/reference/configuration#param-trace-content) is on, and clipped only when [`trace.clip_bytes`](/reference/configuration#param-trace-clip-bytes) is set. |

## Share a directory between processes

Several Dive processes can use one data directory at the same time. Whole files are written to a temporary file and renamed into place, so a reader never sees a partial write. Appends to a thread are serialized by its lock file. When two processes record the same tool shape, the last write wins.

Keep the directory on a local filesystem. File locks aren't reliable on network filesystems such as NFS.

## Back up and reset

- To back up your state, copy the directory.
- To discard learned shapes, delete `shapes/`. Dive records them again as tools run.
- To delete a thread, use [`dive thread rm`](/reference/cli/thread/rm). It also removes the files in `files/` that no other thread refers to. Files in an S3 bucket are kept, since threads on another machine may refer to them.
