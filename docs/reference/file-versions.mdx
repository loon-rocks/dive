## Check which versions your Dive reads

[`dive version`](/reference/cli/version) prints the version Dive writes for each kind of file, and the oldest it still reads when that differs:

```bash
dive version
```

`dive version --json` reports both numbers for every kind under `fileVersions`, as `current` and `oldest`.

## Compatibility

- Dive reads every version from the oldest it supports to the current one. It upgrades an older file in memory as it loads and leaves the file on disk unchanged.
- Dive refuses a file outside that range before reading its contents. The error names the file, the version it found and the versions Dive reads.

Files Dive writes, such as a plan saved from the workbench, always carry the current version. A Dive release that doesn't read that version refuses them, even if they use no new keys.

## Deprecation

Dive currently reads every file version, back to version 1. A future release will drop the oldest versions, and a deprecation process will give you notice and time to migrate before it does.

## Upgrade your files

Run the migrate command for each file you want to bring to the current version. A file already at the current version is left untouched. Commit the migrated files so everyone on your team moves together.

```bash
dive config check
dive config migrate
dive config migrate --global
dive plan migrate .dive/plans/weekly_changes.yaml
dive tool migrate .dive/tools/summarize.yaml
dive agent migrate .dive/agents/release_notes.yaml
```

- **config.toml.** `dive config check` reports each config file's version as `current`, `migrate`, `too new` or `too old`. `dive config migrate` keeps comments and layout. Dive upgrades the global and project files separately, so they can be at different versions. In a terminal, Dive prints a reminder to migrate when it loads an older config file.
- **Plan, tool and agent files.** Migrating keeps the order of keys and the comment block at the top of the file. Comments further down are dropped, and the command reports how many.

## Files outside the range

- A plan file Dive can't read is left out of the catalog. `dive plan list --json` lists it under `skipped`, and running it by name reports the version problem.
- A tool file Dive can't read fails tool loading with the file's name.
- An agent file Dive can't read is reported with its path by `dive agent list` and `dive agent validate`.
- A `pack.toml` or `packs.lock` Dive can't read stops the pack from installing or loading, with the file's name.

## Data directory upgrades

Dive upgrades an older data directory in place the first time a newer release opens it. Concurrent Dive processes wait for the upgrade to finish rather than run it twice. Afterwards, releases that don't read the new version refuse the directory, so copy it first if you may need to go back to an older Dive.
