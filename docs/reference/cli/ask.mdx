Runs one turn of the default `chat` agent, or the agent named with `--agent`, and streams its answer to stdout. Piped stdin is appended to the message as input context.

Put `--session` after the message, since it takes an optional value. On an existing session, `--agent` must name the agent the session started with.

With `--json`, prints `{content, tool_calls_made, tools_used, usage, session_id, run_id, agent}` instead of streaming.

## Arguments

<ParamField path="MESSAGE" type="string">
  The message; reads stdin when omitted and piped
</ParamField>

## Options

<ParamField query="--agent" type="string">
  Run a named agent instead of the default `chat` agent

  Format: `AGENT`.
</ParamField>

<ParamField query="--session" type="string">
  Continue a session: `--session <id>` for a specific one, bare `--session` for the most recent chat. Omit to start a new session

  Format: `SESSION`.

  The value is optional: `--session` on its own is accepted.
</ParamField>

<ParamField query="--json" type="boolean">
  Emit a JSON envelope instead of streaming text
</ParamField>

<ParamField query="--no-stream" type="boolean">
  Print the final answer only, without streaming
</ParamField>

## Global options

<ParamField query="-v, --verbose" type="integer">
  Increase log verbosity (-v info, -vv debug, -vvv trace)
</ParamField>

<ParamField query="--identity" type="string">
  Act as this [identities] entry: runs get a run token minted for its tenant and user, which http tools send to the app

  Format: `IDENTITY`.
</ParamField>

<RequestExample>

```bash Usage
dive ask [OPTIONS] [MESSAGE]
```

```bash Example 1
dive ask "Which issues are blocking the release?"
```

```bash Example 2
git diff | dive ask "Review this diff"
```

```bash Example 3
dive ask --agent release_notes "What shipped this week?"
```

```bash Example 4
dive ask "And the week before?" --session
```

</RequestExample>
