Refuses a git tree with uncommitted changes, then compares every public item's name, input schema and output schema with the newest vX.Y.Z tag. A removed or renamed item, a new required input, or a removed or retyped input or output property needs a major; a new item, optional input or output property needs at least a minor. A major also needs `plans/migrations/migrate_v<N>.yaml` or a `## v<N-1> to v<N>` section in MIGRATING.md. Then it runs `graph pack test` and creates the annotated tag. The first release skips the comparison and is v1.0.0 for major, v0.1.0 for minor and v0.0.1 for patch. Push the tag yourself.

## Arguments

<ParamField path="BUMP" type="enum<string>" required>
  Which part of the version to raise

  Available options: `patch`, `minor`, `major`
</ParamField>

<ParamField path="PATH" type="string" default=".">
  The pack's directory: the root of its git repository
</ParamField>

## Options

<ParamField query="--json" type="boolean">
  Print a JSON envelope instead of text
</ParamField>

## Global options

<ParamField query="-v, --verbose" type="integer">
  Increase log verbosity (-v info, -vv debug, -vvv trace)
</ParamField>

<RequestExample>

```bash Usage
graph pack release [OPTIONS] <BUMP> [PATH]
```

```bash Example 1
graph pack release minor
```

```bash Example 2
graph pack release major ../graph-pack-files
```

</RequestExample>
