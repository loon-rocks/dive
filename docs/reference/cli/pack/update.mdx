A pack whose installed release tag now points at a different commit than packs.lock recorded is refused and left as installed: a published release must never move. The same holds when a clone checks out a different commit than git ls-remote reported. Branch-tracking packs are exempt, and a pinned pack is skipped without contacting the remote.

## Arguments

<ParamField path="NAME" type="string[]">
  Packs to update; every pack in the layer when omitted
</ParamField>

## Options

<ParamField query="--force" type="boolean">
  Overwrite a copy whose content differs from packs.lock
</ParamField>

<ParamField query="--major" type="boolean">
  Cross to each newer major in turn: run its migration as a dry run, show the diffs, ask, apply, then move ref to that major
</ParamField>

<ParamField query="--yes" type="boolean">
  Accept every migration and major without asking (required when there is no terminal)
</ParamField>

<ParamField query="--global" type="boolean">
  Target the global layer (~/.config/graph/) instead of the project's ./.graph/
</ParamField>

<ParamField query="--dir" type="string">
  Target this graph directory, laid out like .graph/ (config.toml, packs/, packs.lock)

  Format: `PATH`.
</ParamField>

<ParamField query="--json" type="boolean">
  Print a JSON envelope instead of text
</ParamField>

## Global options

<ParamField query="-v, --verbose" type="integer">
  Increase log verbosity (-v info, -vv debug, -vvv trace)
</ParamField>

<RequestExample>

```bash Usage
graph pack update [OPTIONS] [NAME]...
```

</RequestExample>
