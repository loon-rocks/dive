Every command reports success or failure through its exit code. Scripts and CI jobs should branch on the exit code, not on the text a command prints.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | The command succeeded. |
| `1` | The command failed, or an edit was refused. Details are on stderr. |
| `2` | The arguments were invalid. graph prints usage help to stderr. |
| `3` | `graph plan run` was missing an input, or an input didn't match the plan's `input_schema`. The schema is printed to stderr. |
| `4` | A plan's `exit` step ended the run with `status: error`. |

A tool that reports an error during `graph tools test --json` still exits `0`: the call completed, and the result's `isError` field says the tool failed.

## Output streams

stdout carries only the command's result: an answer, a plan's output, a listing, or a `--json` envelope. Progress, warnings and error messages go to stderr.

When graph refuses a request, such as an invalid plan or a rejected edit, `--json` still prints the envelope describing why to stdout before exiting `1`. Other failures are reported on stderr only.
