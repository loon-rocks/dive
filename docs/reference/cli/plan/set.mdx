Sets one attribute, named as it appears in the plan file. `solver` and `output` are the two finish modes, so setting one clears the other. Changing `identifier` writes a new file and leaves the old one in place.

An edit is refused if it adds a validation problem, and a refused edit exits 1 and leaves the file untouched. Problems that were already there never block an edit; they are reported as `preExistingProblems`.

Every edit rewrites the whole file, so YAML comments are dropped and flow mappings become block mappings.

## Arguments

<ParamField path="NAME|PATH" type="string" required>
  The plan's identifier or YAML file path
</ParamField>

<ParamField path="ATTRIBUTE" type="enum<string>" required>
  The attribute to set

  Available options: `name`, `description`, `identifier`, `exemplars`, `requires_servers`, `input_schema`, `solver`, `output`
</ParamField>

<ParamField path="VALUE" type="string[]" required>
  One value; `exemplars` and `requires_servers` accept several. `input_schema`, `solver`, and `output` take JSON, @file, or -
</ParamField>

## Options

<ParamField query="--json" type="boolean">
  Print a JSON envelope instead of text
</ParamField>

## Global options

<ParamField query="-v, --verbose" type="integer">
  Increase log verbosity (-v info, -vv debug, -vvv trace)
</ParamField>

<RequestExample>

```bash Usage
dive plan set [OPTIONS] <NAME|PATH> <ATTRIBUTE> <VALUE>...
```

```bash Example 1
dive plan set weekly_changes description "Summarize the commits merged since a ref"
```

```bash Example 2
dive plan set weekly_changes exemplars "What changed this week?" "What shipped since {{release_version}}?"
```

```bash Example 3
dive plan set weekly_changes input_schema @schema.json
```

</RequestExample>
