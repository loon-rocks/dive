title: "dive plan run"

Resolves every step's tool first and refuses to start if any is missing. A solver plan streams its answer to stdout, an output plan prints its JSON, and a silent plan prints nothing.

Missing or invalid inputs exit 3 with the input schema on stderr. An exit step that asserts an error exits 4.

## Arguments

<ParamField path="NAME" type="string" required>
  The plan's identifier, as `dive plan list` prints it
</ParamField>

<ParamField path="JSON|@FILE|-" type="string">
  Inputs as a JSON object: inline (`'{"a":1}'`), `@file.json`, or `-` for stdin
</ParamField>

## Options

<ParamField query="--input" type="string[]">
  Override individual input keys (applied on top of the JSON document)

  Format: `KEY=VALUE`.
</ParamField>

<ParamField query="--json" type="boolean">
  Print a JSON envelope instead of text
</ParamField>

## Global options

<ParamField query="-v, --verbose" type="integer">
  Increase log verbosity (-v info, -vv debug, -vvv trace)
</ParamField>

<RequestExample>

```bash Usage
dive plan run [OPTIONS] <NAME> [JSON|@FILE|-]
```

```bash Example 1
dive plan run weekly_changes
```

```bash Example 2
dive plan run weekly_changes '{"base":"{{release_version}}"}'
```

```bash Example 3
dive plan run weekly_changes @inputs.json --input base=v0.14.0
```

</RequestExample>
