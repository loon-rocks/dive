Prints the PEM public key that verifies the run tokens Dive mints for dev identities and `dive serve --dev-key`, creating the key on first use. It's also written to `serve/dev-key.pub.pem` in the data directory. Give it to an app that runs elsewhere, such as in a container, as `DIVE_DEV_PUBLIC_KEY`. Refused when `DIVE_ENV` or `[identity].environment` is `production`.

## Options

<ParamField query="--dir" type="string">
  Project directory, the one holding `.dive/`; defaults to the current directory

  Format: `PATH`.
</ParamField>

## Global options

<ParamField query="-v, --verbose" type="integer">
  Increase log verbosity (-v info, -vv debug, -vvv trace)
</ParamField>

<ParamField query="--identity" type="string">
  Act as this [identities] entry: runs get a run token minted for its tenant and user, which http tools send to the app

  Format: `IDENTITY`.
</ParamField>

<RequestExample>

```bash Usage
dive dev key [OPTIONS]
```

```bash Example 1
dive dev key
```

```bash Example 2
DIVE_DEV_PUBLIC_KEY="$(dive dev key)" docker compose up
```

</RequestExample>
